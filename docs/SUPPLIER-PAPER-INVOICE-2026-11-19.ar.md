# DeenBook — إرفاق صورة الفاتورة الورقية لمورد (19 نوفمبر 2026)

## النتيجة
- بطاقة اختيارية في شاشة **تسجيل فاتورة مورد (بضاعة واردة)**، قبل اختيار طريقة الإدخال: تصوير بكاميرا الهاتف أو اختيار صورة موجودة.
- تبقى الصورة محفوظة في الشاشة عند التبديل بين «مبلغ إجمالي سريع» و«تفصيل الأصناف والأسعار».
- معاينة الصورة وحذفها قبل اعتماد الفاتورة.
- تُرسل الصورة **ضمن نفس عملية الفاتورة ومعرّف OperationId** لضمان حفظ الصورة والفاتورة معًا ومنع التكرار عند إعادة المحاولة.
- في وضع عدم الاتصال: تحفظ الصورة بصيغة base64 مع العملية في صندوق المزامنة الآمن. لا تختفي بتغيير وضع الإدخال، وتُرفع مع الفاتورة عند نجاح المزامنة.
- في شاشة المورد وكشف الحساب يظهر زر «عرض صورة الفاتورة الورقية» للفاتورة المصورة. تنزيل الصورة يتطلب صلاحية دخول لنفس المحل، وتُخزّن نسخة محلية بعد فتحها لأول مرة للعرض لاحقًا بدون إنترنت.

## التغييرات المطلوبة على الخادم
- `EntryInput`: `InvoicePhotoBase64` و `InvoicePhotoContentType` اختياريان.
- `LedgerEntry`: علامة `HasInvoicePhoto` دون تحميل الصورة في كشوف الحساب.
- جدول جديد `LedgerInvoicePhotos` يتضمن صورة JPG/PNG محمية مرتبطة بمعرّف الحركة.
- `GET /api/transactions/{id}/invoice-photo` مسار محمي يعيد الصورة من المحل المصرّح له فقط.
- الصور تُخزن داخل قاعدة البيانات، لا في مجلد استضافة قد تختفي ملفاته عند نشر نسخة جديدة.
- حد الصورة: 1 ميجابايت بعد الضغط. لا تُقبل إلا JPG/PNG وتُفحص البصمة الأولية للملف.
- حفظ الفاتورة والصورة يتم في `SaveChangesAsync` واحد. يبقى Hash الحركات القديمة دون صور متوافقًا مع الخادم السابق.

## قاعدة البيانات — ضروري قبل نشر Flutter
**لا تستبدل ملفات إعدادات الاتصال، ولا تنشئ Migration قبل دمج ملفات الـ Backend في آخر نسختك الفعلية.**
1. ادمج تغييرات الحزمة في مشروع الـ Backend الحالي؛ هناك تعديلات سابقة مستقلة للـ Credit Limit والبيع بالوزن وفواتير الموردين. لا تستبدل هذه التعديلات بنسخة Backend قديمة.
2. اعمل Rebuild. من Package Manager Console مع Startup Project `DeenBook.Api` نفّذ:

```powershell
Add-Migration AddSupplierInvoicePaperPhoto -Project DeenBook.Infrastructure -StartupProject DeenBook.Api -Context AppDbContext -OutputDir Persistence/Migrations
```

3. **راجع** ملف Up(): يجب أن يضيف عمود Boolean في Entries وجدول LedgerInvoicePhotos مع علاقة بالحركات وبدون حذف جداول أو أعمدة أخرى.
4. إذا وجد اختلافات غير متوقعة، توقف ولا تنفذ Update-Database قبل معالجة Snapshot.
5. بعد نجاح المراجعة والنسخ الاحتياطي لقاعدة البيانات:

```powershell
Update-Database -Project DeenBook.Infrastructure -StartupProject DeenBook.Api -Context AppDbContext
```

6. انشر Backend المعدّل **قبل** بناء/نشر نسخة Flutter المصورة.

## اختبارات مطلوبة قبل النشر
1. إنشاء فاتورة مورد **مبلغ سريع** دون صورة، وظهورها في الكشف.
2. إنشاء فاتورة مورد **مبلغ سريع + صورة** وظهور زر العرض وفتح صورة JPG الأصلية.
3. إنشاء فاتورة مفصلة **+ صورة** مع تغيير وضع الإدخال ذهابًا وإيابًا قبل الحفظ.
4. الالتقاط بدون إنترنت، إغلاق التطبيق وفتحه، التأكد من وجود العملية والصورة، ثم المزامنة مرة واحدة وتأكد عدم تكرار الفاتورة.
5. رفض ملف مزيف/أكبر من 1 ميجابايت مع رسالة واضحة، دون فقدان بيانات الفاتورة.
6. منع فتح صورة فاتورة محل مختلف عبر API.
7. بعد رفع الصورة: إغلاق التطبيق وفتح صورة الفاتورة من كشف المورد، وفتحها مرة ثانية offline بعد تحميلها مرة واحدة.
