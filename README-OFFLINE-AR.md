# DeenBook — مراجعة Flutter: وضع اتصال متقطع، المزامنة، التقارير، التجربة المجانية

## نطاق هذه النسخة

هذه نسخة مصدر للتطوير والاختبار، **ليست نسخة إنتاج نهائية أو تطبيقاً كاملاً يعمل دون اتصال في كل الشاشات**. لم يجرِ تشغيل `flutter analyze` أو `flutter test` في بيئة تجهيز الملفات لعدم توفر Flutter SDK. يجب بناء المشروع واختباره على جهاز أندرويد فعلي قبل أي استخدام مالي.

### المضاف

- حفظ استجابات القراءة التي حمّلها المستخدم أثناء اتصال موثوق داخل تخزين الجهاز المشفر بواسطة Flutter Secure Storage. عند فشل الاتصال يمكن عرض **البيانات المحفوظة مسبقاً** بنفس معايير الطلب. لا تضمن النسخة توفر تفاصيل شاشة لم تُفتح أثناء الاتصال.
- عند إرسال دين أو مشتريات أو دفعة أو مرتجع يُخزّن الطلب ومعرفه الثابت `operationId` قبل المحاولة الشبكية؛ وعند فقد الاتصال يبقى في قائمة انتظار محلية مستقلة لكل محل.
- الاستجابة الرافضة للحركة (400/404/409/422) لا تمحو بياناتها: تُعلَّم محلياً بأنها «تحتاج مراجعة» وتتوقف إعادة المحاولة الآلية لها، ويمكن حذفها بعد مراجعة كشف الحساب والتأكد.
- إعادة المحاولة **بنفس المعرف** بعد اتصال الإنترنت، تلقائياً عند فتح التطبيق/العودة إليه، وكل 45 ثانية أثناء استخدامه، بالإضافة إلى زر يدوي وشاشة «مركز المزامنة».
- ملاحظة واضحة أن المعاملة **محفوظة على الجهاز وليست مثبتة على الخادم**. لا تحتسب المعاملات غير المتزامنة في تقارير الخادم، وتتوقف طباعة التقارير أثناء عدم تزامنها.
- تقارير مفهومة: قبض/دفع بجميع الوسائل، النقد الداخل/الخارج، أرصدة الذمم الحالية، والتنبيه أن صافي النقد لا يساوي الربح.
- تحسينات طفيفة في واجهة إضافة الزبون والمورد والصنف وترتيب القائمة، وإظهار فترة التجربة 14 يوماً عندما يعيد الخادم بياناتها.
- تثبيت بنية الحساب والرموز المالية القديمة والخطط المدفوعة (60/150 شيكل)، دون اختراع حساب ربح لا يدعمه نموذج البيانات.

## حدود مهمة قبل الإنتاج

- **Offline محدود**: لا يمكن إنشاء زبون/مورد/صنف جديد أو تعديل بياناته من دون اتصال؛ هذه العمليات تتطلب تصميم تزامن لعمليات الإنشاء والتعديل مع حل التعارضات وIdempotency على الخادم. البحث في بيانات لم تُخزن سابقاً قد يتعذر أيضاً.
- لا يتم احتساب الدفعات المحلية في الأرصدة الرسمية حتى يؤكّد الخادم وصولها؛ يجب إكمال المزامنة قبل الاعتماد على رصيد المحل.
- يسمح بإعادة فتح الجلسة دون اتصال بعد تسجيل دخول ناجح سابق خلال **7 أيام** كحد أقصى، وفقط إذا لم تنتهِ صلاحية الاشتراك المسجلة محلياً. هذا قيد أمني مؤقت وليس ترخيصاً للعمل Offline بلا حدود.
- المزامنة التلقائية تعمل عندما يكون التطبيق مفتوحاً أو يعود للواجهة. **لا توجد خدمة Android Background Worker** تعمل عندما يكون التطبيق مغلقاً تماماً.
- ملف البيانات المشفرة يعتمد على سعة `flutter_secure_storage`؛ قبل الإنتاج واسع النطاق تحتاج قاعدة محلية SQLite مشفرة أو مخزناً مماثلاً مع فهرسة وترحيل وتجزئة آمنة.
- الاستخدام عبر عدة أجهزة يحتاج اختبارات تعارضات فعلية وسجل تدقيق تفصيلي قبل الاعتماد عليه؛ حالياً تتم مزامنة عمليات الدفتر ذات معرف `operationId` ثابت فقط.
- تحديث الواجهات 1.2.1 موثق في `docs/CHANGES-1.2.1.ar.md`؛ تمت معاينة رابط Gemini الأخير ومقارنة الواجهات به.
- يُمنع إرسال كلمات مرور/بيانات زبائن عبر HTTP. فعّل HTTPS صالحاً على MonsterASP قبل اختبار بيانات فعلية أو إصدار Release.

## 14 يوم تجربة — ما الذي تغير بالخادم؟

- عند **إنشاء محل من لوحة الأدمن** يبدأ الحساب بصلاحية 14 يوماً محسوبة في Backend من `TimeProvider`، بدون إنشاء دفعة وهمية.
- `GET /api/subscription` يُرجع `isTrial` و`trialDaysRemaining`؛ Flutter يعرضها بشكل واضح.
- التجربة لا تنطبق بأثر رجعي على المحلات القديمة. انتهاء التجربة يعيد المستخدم لشاشة الاشتراك.
- ما زال إنشاء الحساب يتم عبر الأدمن، لا توجد شاشة تسجيل ذاتي مع OTP؛ ينبغي عدم الادعاء بوجود تسجيل ذاتي.
- يحتاج نشر Backend المرفق أولاً؛ تغيير Flutter وحده لا يمنح 14 يوماً.

## التشغيل والبناء

```bash
flutter pub get
flutter analyze
flutter test
flutter build apk --debug --dart-define=API_BASE_URL=https://api-deenbook.runasp.net
```

يمكن استخدام `codemagic.yaml` للبناء السحابي من مستودع GitHub خاص. لا ترفع كلمات سر قواعد البيانات أو `key.properties`. تطوير قاعدة البيانات الحالية لم يحتاج migration لهذه الميزة؛ استخدم النسخة الأخيرة من Backend المرفقة مع تحديثات لوحة الأدمن السابقة.

## اختبار القبول المطلوب

1. إنشاء محل جديد بالأدمن والتحقق من `isTrial=true` و`trialDaysRemaining=14` عند أول فتح.
2. تسجيل حركة أونلاين، قطع الشبكة، تسجيل حركتين إضافيتين لنفس الزبون؛ يجب حفظهما منفصلتين ومعرفين مختلفين.
3. إغلاق التطبيق ثم فتحه دون إنترنت، فحص ظهور قائمة الانتظار والبيانات التي سبق تحميلها.
4. إعادة الشبكة ومراقبة انتقال الحركتين إلى الخادم **مرة واحدة فقط** رغم إعادة محاولات المزامنة.
5. مقارنة رصيد الخادم والإجماليات والتقرير بعد المزامنة، وفحص عدم تكرار دفعة تأخر رد الخادم عليها.
6. تغيير الاشتراك أو إيقاف المحل أثناء الانقطاع: يجب ألا يحصل ترخيص تلقائي جديد من الجهاز.
7. اختبار على شاشات 320 و390 و768، مع خط Cairo وأزرار كبيرة وواضحة.

هذه النسخة نقطة تطوير مفيدة وليست إقراراً باجتياز الخطوات السابقة.
