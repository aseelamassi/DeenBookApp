# إصلاح الاتصال وطلب الاشتراك — Flutter 1.1.1

## رابط الخادم

القيمة الصحيحة لهذه النسخة:

```text
https://api-deenbook.runasp.net
```

التطبيق يضيف `/api/auth/login` و`/api/subscription` وبقية المسارات بنفسه. لا تضف `/api` ولا نقطة في النهاية. النسخة الجديدة تنظف اللواحق `/api` و`/api/` و`/api.` لمنع تكرار المسار، وتستخدم رابط الاستضافة أعلاه افتراضياً بدلاً من عنوان محاكي Android المحلي.

`API_BASE_URL` إعداد وقت البناء. أوقف التطبيق تماماً وأعد تشغيله أو بناءه بعد تغييره؛ Hot Reload لا يكفي لتغيير `--dart-define`.

## نتيجة فحص الاستضافة

في فحص غير مسجل الدخول بتاريخ 27 أكتوبر، وأُعيد بتاريخ 28 أكتوبر 2026:

- أعادت `http://api-deenbook.runasp.net/api/subscription` و`/api/subscription/plans` و`/api/capabilities` الحالة 401. هذا يعني أن مسارات HTTP تستجيب وتطلب المصادقة؛ لا يعني أن الحساب أو قاعدة البيانات اختُبرا.
- فشلت اتصالات HTTPS من بيئة الفحص برسالة 503 تشير إلى تعذر الاتصال بالجهة البعيدة. راجع تفعيل HTTPS وشهادة النطاق من الاستضافة؛ لم نغيّر إعدادات الاستضافة أو نؤكد سبب الفشل من لوحة التحكم.
- الحالة 404 على جذر الموقع أو `/api.` لا تختبر صحة مسار API فعلي.

## تفعيل HTTPS على MonsterASP

بحسب [دليل الاستضافة الرسمي](https://help.monsterasp.net/domains-https/https/lets-encrypt)، الخطة المجانية تحتاج تذكرة دعم لتفعيل HTTPS بعد رفع التطبيق. افتح تذكرة واطلب تفعيله للنطاق `api-deenbook.runasp.net`. إذا كانت الخطة تسمح بالتفعيل الذاتي، افتح الموقع من Websites ثم HTTPS وفعل الشهادة للنطاق.

بعد التفعيل، افتح:

```text
https://api-deenbook.runasp.net/api/subscription
```

الحالة 401 بدون توكن نتيجة متوقعة. أخطاء الشهادة أو تعذر الاتصال تحتاج إصلاحاً على الاستضافة قبل اختبار تسجيل الدخول. لا تفعّل تحويل HTTP إلى HTTPS قبل أن يعمل HTTPS. لا تتجاوز التحقق من الشهادة؛ إصدار Release يرفض HTTP.

## إعادة تشغيل Flutter

### تشغيل Windows بأمر واحد

فك ضغط المشروع كاملاً، ثم افتح PowerShell داخل مجلد `DeenBook-Flutter` وشغّل الفحص:

```powershell
.\Start-DeenBook.ps1 -CheckOnly
```

هذا الفحص لا يحتاج Flutter ولا حساب دخول، ويرسل طلب GET واحداً فقط إلى `/api/subscription/plans` عبر HTTPS. النتيجة المتوقعة لهذا المسار المحمي هي 401؛ تعني أن الاتصال يستجيب ويطلب المصادقة، ولا تثبت صحة بيانات الحساب أو اتصال قاعدة البيانات. لا يتبع الفحص التحويلات ولا يتجاوز شهادة HTTPS، ولا يقرأ جسم الرد أو يرسل بيانات حساب.

عندما ينجح الفحص، شغّل:

```powershell
.\Start-DeenBook.ps1
```

لتحديد رقم الإدارة، استبدل المثال التالي بالرقم الدولي الحقيقي:

```powershell
.\Start-DeenBook.ps1 -SupportPhone '970XXXXXXXXX'
```

المثال الذي يحتوي على X يُرفض عمداً. عند غياب الرقم، يظهر تنبيه ويعمل التطبيق مع عرض تفاصيل الطلب للنسخ؛ لن تُفتح محادثة واتساب. يقبل الإعداد الرقم الدولي مع `+` أو `00` والمسافات. لا يحفظ الملف الرقم في مصدر التطبيق، بل يمرره لإعدادات تشغيل Flutter.

يمكن إضافة `-Device chrome` للويب، أو اسم الجهاز من `flutter devices`. ويمكن تحديد مضيف HTTPS آخر عبر `-BaseUrl`. تزال لاحقة `/api` أو `/api.` والمسافات من الرابط قبل الفحص والتشغيل، وتبقى المسارات الفرعية مثل `/shop` محفوظة. تشغيل خادم محلي عبر HTTP متاح بأمر Flutter المباشر أدناه، وليس عبر هذا الملف المخصص للاستضافة.

عند فشل الفحص، لن يبدأ `flutter pub get` أو `flutter run`. يعرض الملف سبباً مناسباً للحالات 404، والتحويلات، ورفض الوصول، وأخطاء الخادم أو الاتصال الآمن. إصلاح هذه الحالات قد يحتاج تعديل الاستضافة؛ الملف لا يفعّل HTTPS بنفسه. عند ظهور 503 حالياً، راجع تفعيل HTTPS وفق التعليمات أعلاه ثم أعد الفحص من جهازك.

بعد نجاح الفحص، يحتاج التشغيل Flutter في `PATH` وجهازاً أو محاكياً متاحاً. تُنفّذ الأوامر داخل مجلد المشروع حتى لو استدعيت الملف من مجلد آخر، ويُستعاد المجلد السابق عند الانتهاء. الملف محفوظ بترميز UTF-8 مع BOM لقراءة العربية في Windows PowerShell 5.1؛ تحقق التشغيل الآلي المرفق أُجري باستخدام PowerShell 7 على Linux.

### التشغيل المباشر

من مجلد Flutter:

```powershell
flutter pub get
flutter run --dart-define=API_BASE_URL=https://api-deenbook.runasp.net
```

ولإعداد رقم واتساب الإدارة، استبدل رقم المثال برقم حقيقي بالصيغة الدولية:

```powershell
flutter run --dart-define=API_BASE_URL=https://api-deenbook.runasp.net --dart-define=SUPPORT_PHONE=970XXXXXXXXX
```

لبناء Android للنشر، احتفظ بإعداد توقيع التطبيق ثم استخدم نفس الإعدادات مع `flutter build appbundle --release`. لم نُصدر APK أو IPA أو نثبت تطبيقاً على هاتف ضمن هذا الإصلاح.

في Flutter Web، يلزم أيضاً أن تسمح CORS في API بأصل الموقع الذي يشغّل Flutter فعلياً. لا تضف CORS إلى Flutter، ولا تستخدم عنوان SQL Server كعنوان API.

## طلب الاشتراك

- السعر: شهر واحد بـ60 شيكل أو ثلاثة أشهر بـ150 شيكل.
- زر المتابعة يفتح مسودة واتساب موجهة إلى رقم الإدارة. المستخدم يضغط إرسال داخل واتساب.
- عند عدم ضبط الرقم أو فشل فتح واتساب، يظهر «لم يُرسل الطلب» مع النص القابل للنسخ. لا يحدث نسخ تلقائي، ولا تظهر رسالة نجاح إرسال.
- بعد اختيار النسخ، تظهر «تم نسخ التفاصيل فقط؛ لم يُرسل الطلب».
- إنشاء الحساب وتسجيل الدفعة والتفعيل تتم عبر لوحة الإدارة الحالية. لا يوجد في الخادم الحالي endpoint لاستقبال طلب تسجيل أو اشتراك من زائر غير مسجل. هذا الإصلاح لا يضيف دفعاً إلكترونياً أو إرسالاً تلقائياً.

لم يُضبط رقم إدارة تخميني في المشروع. يجب تحديد `SUPPORT_PHONE` عند البناء لتشغيل التواصل المباشر.

## حدود الإصلاح

رسائل التطبيق تميز الآن انقطاع الوصول، انتهاء المهلة، فشل الاتصال الآمن، المسار 404، التحويل إلى عنوان آخر، وأخطاء الخادم 5xx. لا تفترض جميع هذه الأخطاء وجود مشكلة في إنترنت المستخدم. لا يعاد إرسال طلب مالي تلقائياً نتيجة أي من هذه الأخطاء.

هذه التغييرات لا تحتاج migration جديدة. مصدر الـAPI المرفق مطابق للنسخة المستقلة بتاريخ 25 أكتوبر؛ اتبع دليل الترقية الخاص به فقط إن لم تطبق تحديث قاعدة البيانات السابق.
