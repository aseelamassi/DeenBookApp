# DeenBook — تصنيف الأصناف وحاسبة الوزن والمبلغ (15 نوفمبر 2026)

## الملفات

- `DeenBook-Flutter-Weight-Sales-2026-11-15.zip`: مصدر Flutter الكامل المبني على آخر نسخة **Credit Limit**.
- `DeenBook-Flutter-Weight-Sales-Patch-2026-11-15.zip`: ملفات Flutter المعدلة فقط.
- `DeenBook-Backend-Weight-Sales-Patch-2026-11-15.zip`: ملفات Backend المعدلة فقط، بدون ملفات الإعدادات أو أسرار.

## الميزات

- إضافة `PricingMode` للصنف: `Weight` (بالكيلو) أو `Piece` (بالقطعة). التصنيف التجاري `Category` موجود أصلاً ويُستخدم لشرائح الأقسام.
- شاشة إضافة وتعديل صنف: أقسام سريعة + تحديد نوع التسعير؛ يتغير عنوان سعر البيع وفق الطريقة.
- شاشة مشتريات الدين: البحث عن صنف داخل الصفحة مع فلاتر أقسام أفقية، وحاسبة وزن ⇄ مبلغ للأصناف الموزونة.
- أزرار وزن سريع 250/500/1000 غرام، وأزرار مبلغ 5/10/15/20 شيكل، وإدخال حر للغرام أو الكيلو أو المبلغ.
- دفتر الزبون وتصدير التقارير: يعرض اسم الصنف والوزن والمجموع. إذا أدخلت البيعة بالمبلغ تُحفظ `ByAmount=true` داخل `ItemsJson` وتُعرض بصيغة «بـ X شيكل = Y غرام».
- الحسابات تستخدم أغورات صحيحة ودقة 1 غرام في الوزن؛ عند التقريب، السعر الفعلي قد يختلف عن المبلغ المطلوب بقرش.
- فواتير الموردين تظل منفصلة عن قائمة الأصناف ولا تتأثر.

## مهم: تحديث قاعدة البيانات

يتطلب هذا الإصلاح إضافة العمود `PricingMode` إلى جدول `Products`، ولا يوجد Migration مولّد في هذه الحزمة، لأننا لا نملك حالة الـ Migrations الفعلية على سيرفرك، وظهر سابقاً تعارض `PendingModelChangesWarning`.

1. خذي نسخة احتياطية من قاعدة البيانات قبل التحديث.
2. ادمجي ملفات Backend في مشروعك الحالي دون استبدال appsettings أو تعديلاتك الأخرى.
3. شغّلي `Build Solution` في Visual Studio.
4. بعد أن تتأكدي من أن جميع الـ Migrations السابقة متطابقة ومطبقة، شغّلي **Package Manager Console** (Default Project `DeenBook.Infrastructure` و Startup Project `DeenBook.Api`):

```powershell
Add-Migration AddProductPricingMode -Project DeenBook.Infrastructure -StartupProject DeenBook.Api -Context AppDbContext -OutputDir Persistence/Migrations
```

5. راجعي دالة `Up()` في الملف الجديد: المتوقع إضافة `PricingMode` فقط إلى `Products` بنوع `nvarchar(12)`، وقيمة افتراضية `Piece`. **إذا ظهر حذف أو تغييرات غير مقصودة، لا تنفذي التحديث.**
6. **طبقي Migration أولًا** بعد مراجعته من Package Manager Console:

```powershell
Update-Database -Project DeenBook.Infrastructure -StartupProject DeenBook.Api -Context AppDbContext
```

7. توجد أصناف قديمة وحدتها `كغم` قبل وجود نوع التسعير. بعد نجاح `Update-Database`، نفّذي هذا الاستعلام مرة واحدة على قاعدة البيانات الصحيحة (بعد أخذ نسخة احتياطية) لنقلها إلى `Weight`:

```sql
UPDATE dbo.Products
SET PricingMode = 'Weight'
WHERE Unit IN (N'كغم', N'كيلو', N'kg') AND PricingMode = 'Piece';
```

8. انشري Backend أولاً، ثم تطبيق Flutter الجديد. لا تعتمدي هذه التحديثات للإنتاج قبل نجاح الاختبارات.

### إن كان لديك Migration Credit Limit لم يُطبق

يجب التأكد أولاً من تطابق الـ Model مع الـ Snapshot؛ لا تنشئي Migration جديداً فوق Snapshot غير متطابق ولا تعطي الأمر `Update-Database` قبل فحص ملف الترحيل.

## التوافق والقيود

- **لم تُعدّل** `appsettings.json`، أو عنوان الـ API، أو `pubspec.yaml`، أو `pubspec.lock`، أو Gradle/Codemagic، أو إصدارات أي حزمة.
- حقول `LedgerItem` تحفظ كـ JSON داخل `ItemsJson`. حقل `ByAmount` اختياري ولا يظهر في بيانات الفواتير القديمة، للحفاظ على توافقيّة آلية منع التكرار.
- `Quantity` تحفظ بالكيلو إلى 3 منازل عشرية (= غرام واحد)، والمجموع يحسب لأقرب أغورة. مثال: 20₪ بسعر 28₪/كغم → 714 غرامًا → 19.99₪، وتظهر هذه القيمة قبل الاعتماد.
- قراءة قوائم الأصناف دون إنترنت تعتمد على توفر بيانات محلية محفوظة سابقاً؛ هذا الإصلاح لا يضيف مزامنة كاملة للأصناف الجديدة دون إنترنت.
- لم يتوفر Flutter SDK أو .NET SDK هنا، لذا **لم نتمكن من إجراء build أو تشغيل الاختبارات الفعلية**. أضفنا اختبارات وحدات تحتاج إلى تشغيلها محلياً.

## اختبارات تشغيل مقترحة

1. أضيفي «جبنة» إلى «ألبان وأجبان»، `Weight`، سعر الكيلو 28₪.
2. من مشتريات الدين اختاري «ألبان وأجبان» والجبنة: 500 غ = 14₪، و250غ = 7₪.
3. أدخلي مبلغ 10₪ → 357غ و10₪، وأدخلي 20₪ → 714غ و19.99₪.
4. بعد الحفظ، افتحي كشف الزبون وتحققي من ظهور وزن/سعر كل صنف مع الدفعة والدين.
5. سجّلي صنفًا بالقطعة للتأكد من استمرار مسار الشراء القديم، وجرّبي تسجيل فاتورة مورد للتأكد من بقائها مستقلة.
6. جرّبي إعادة مزامنة الحركة في حالة انقطاع الرد من الخادم لتجنب ظهور حركة مكررة.
